# Release Strategy

## Versioning

Seneve uses Semantic Versioning:

```text
v0.1.0
v0.2.0
v1.0.0
v2.0.0
```

## Release Requirements

Every release requires:

- passing tests
- updated documentation
- migration review
- release notes
- version increment
- Git tag
- GitHub Release

## Epic Release Notes

Each completed Epic must record:

- implemented features
- modified modules
- database changes
- API changes
- test coverage summary
- documentation updates
- known limitations
- recommended next milestone
